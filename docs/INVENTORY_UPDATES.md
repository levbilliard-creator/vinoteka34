# Обновление ассортимента

Текущий ассортимент сверяется с актом инвентаризации от 31.10.2026.
На сайт попадают 644 строки с положительным фактическим остатком.
Цена берётся из колонки V (розничная), наличие — из N (факт).
Бухгалтерский остаток Q не определяет наличие на сайте.

Сохранены 320 прежних ID; 324 карточки добавлены. 233 прежние карточки
сохранены в `data/products-archive.json`. Они не входят в поиск, категории
и рекомендации, но открываются по старой ссылке с пометкой отсутствия.
Архивные цены сохраняются в данных для истории и не выводятся покупателям.

Новые акты нужно хранить вне публичного репозитория. В репозиторий не
попадают складские количества, расхождения и суммы товарного остатка.

## Порядок следующего обновления

1. Сверить фактический остаток и розничные цены нового акта.
2. Найти точные `inventory_key` среди активных и архивных карточек.
   Для переименованных строк вручную подтвердить прежний ID; объём, цвет,
   год, линейка и подарочный набор могут определять отдельный товар.
3. Подготовить карту соответствий с SHA256 нового файла. Старую карту
   нельзя применять к другому акту — импорт останавливается.
4. Использовать `scripts/import_inventory.py` с приватным путём к акту
   и проверенной картой. Неподтверждённые совпадения не объединять.
5. Проверить все строки и цены, архив, изображения и пользовательский поиск.
6. После push в main публикация в существующий бакет Яндекса выполняется
   автоматически с предварительной резервной копией.

Если товар вернулся, использовать его ID из архива в проверенной карте:
импорт возвращает карточку в активный каталог и исключает её из архива.
Не удалять архив и не использовать его ID для другого товара.

`docs/inventory-2026-10-31-map.json` фиксирует проверенные совпадения,
а `docs/inventory-2026-10-31-release.json` — состав и цены выпуска.
Названия очищены от служебных фраз. Неполные сведения не дополняются догадками.
Спорные цвет/страна/объёмы отмечены в карте и не публикуются до уточнения.

## Фото

`docs/product-image-map.json` содержит явные проверенные привязки ID → файл.
Для найденных в интернете фото сохранены адрес страницы, URL изображения
и описание идентичности. Файлы хранятся локально в `assets/wines`.
Автоматический нечёткий подбор фото в браузере запрещён: отсутствие фото
отображается заглушкой. Оригиналы прежних фотографий сохранены.
